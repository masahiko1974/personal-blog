【Unity输入管理#1】移动端点击、拖拽、长按事件检测

在移动端游戏开发中，处理用户输入是一个非常常见的需求。然而，如果每个需要检测输入的地方都单独实现输入检测逻辑，会导致大量重复代码，增加维护难度。

本文将从简单的输入检测实现开始，逐步将其抽离到一个独立的输入管理类中，从而提高代码的可维护性和复用性。

基础实现

首先实现简单的输入检测（以长按检测和拖拽检测为例），过程中将使用Unity的Touch输入系统来检测用户的触摸操作。

长按检测

长按逻辑：

  • 长按的判定基于手指持续触摸的时间是否超过阈值（longPressThreshold）。
  • 一旦判定为长按，isLongPress会被设置为true，并输出长按开始和结束的日志。

长按实现：

  • 每一帧检测是否有单点触摸，如果有，获取触摸点并记录触摸开始时间。
  • 根据触摸的不同阶段处理逻辑：
    • TouchPhase.Began: 记录触摸开始的时间。
    • TouchPhase.Stationary: 如果当前不是正在长按，计算当前时间与触摸开始时间的差值，如果超过阈值，判定为长按开始，标记当前正在长按。
    • TouchPhase.Ended: 如果正在长按，标记长按结束。
using UnityEngine;

public class SimpleInputHandler : MonoBehaviour
{
    private bool isLongPress = false;           // 用于标记是否正在长按
    private float touchStartTime;               // 记录触摸开始的时间
    private const float longPressThreshold = 0.5f; // 长按触发的阈值，表示手指持续触摸超过这个时间才判定为长按

    private void Update()
    {
        // 检测是否有单点触摸
        if (Input.touchCount == 1)
        {
            Touch touch = Input.GetTouch(0); // 获取第一个触摸点

            switch (touch.phase)
            {
                case TouchPhase.Began:
                    touchStartTime = Time.time; // 记录触摸开始的时间
                    isLongPress = false;
                    break;

                case TouchPhase.Stationary:
                    if (!isLongPress)
                    {
                        // 计算当前时间与触摸开始时间的差值
                        float duration = Time.time - touchStartTime;
                        if (duration > longPressThreshold)
                        {
                            Debug.Log("Long press started"); // 如果时间超过阈值，判定为长按开始
                            isLongPress = true;
                        }
                    }
                    break;

                case TouchPhase.Ended:
                    if (isLongPress)
                    {
                        Debug.Log("Long press ended"); // 长按结束
                        isLongPress = false;
                    }
                    break;
            }
        }
    }
}

在这个实现中，我们检测用户的长按操作，并在长按开始和结束时输出日志。

拖拽检测

拖拽逻辑：

  • 拖拽的判定基于手指移动的距离是否超过阈值（dragThreshold）。
  • 一旦判定为拖拽，isDragging会被设置为true，并在拖拽过程中持续输出当前拖拽位置（世界坐标）。

拖拽实现：

  • 每一帧检测是否有单点触摸，如果有，获取触摸点并转换为世界坐标。
  • 根据触摸的不同阶段处理逻辑：
    • TouchPhase.Began: 记录触摸开始时的位置。
    • TouchPhase.Moved: 如果当前不是正在拖拽，计算当前触摸点与起始点的距离，如果超过阈值，判定为拖拽开始，标记当前正在拖拽；如果当前正在拖拽，输出拖拽中的位置。
    • TouchPhase.Ended: 如果正在拖拽，标记拖拽结束。
using UnityEngine;

public class SimpleInputHandler : MonoBehaviour
{
    private bool isDragging = false;			// 用于标记是否正在拖拽
    private Vector3 dragStartPos;				// 记录拖拽的起始位置
    private const float dragThreshold = 0.2f;	// 拖拽触发的阈值，表示手指移动超过这个距离才判定为拖拽

    private void Update()
    {
        // 检测是否有单点触摸
        if (Input.touchCount == 1)
        {
            Touch touch = Input.GetTouch(0); // 获取第一个触摸点
            Vector3 touchPos = Camera.main.ScreenToWorldPoint(touch.position); // 将屏幕坐标转换为世界坐标

            switch (touch.phase)
            {
                case TouchPhase.Began:
                    dragStartPos = touchPos; // 记录触摸开始时的位置
                    break;

                case TouchPhase.Moved:
                    if (!isDragging)
                    {
                        // 计算当前触摸点与起始点的距离
                        float distance = Vector2.Distance(touchPos, dragStartPos);
                        if (distance > dragThreshold)
                        {
                            Debug.Log("Drag started"); // 如果距离超过阈值，判定为拖拽开始
                            isDragging = true;
                        }
                    }
                    if (isDragging)
                    {
                        Debug.Log($"Dragging to position: {touchPos}"); // 输出拖拽中的位置
                    }
                    break;

                case TouchPhase.Ended:
                    if (isDragging)
                    {
                        Debug.Log("Drag ended"); // 拖拽结束
                        isDragging = false;
                    }
                    break;
            }
        }
    }
}

在这个实现中，我们检测用户的拖拽操作，并在拖拽开始、移动和结束时输出日志。

输入管理类

虽然基础实现方式简单直接，但它存在一些问题：

  • 代码重复：如果多个GameObject都需要处理点击、拖拽和长按事件，每个GameObject都需要编写类似的输入检测代码。
  • 维护困难：当输入逻辑需要修改时，需要在多个地方进行更改。
  • 耦合度高：输入逻辑与GameObject的业务逻辑耦合在一起，难以复用。

为了解决这些问题，我们可以将输入检测逻辑抽离到一个独立的输入管理类中。

using UnityEngine;
using System;

public class InputHandler : BaseMonoMgr<InputHandler>
{
    // 拖拽事件：拖拽开始时触发，参数为当前触摸位置
    public event Action<Vector3> OnDragStart;
    // 拖拽事件：拖拽中触发，参数为当前触摸位置
    public event Action<Vector3> OnDrag;
    // 拖拽事件：拖拽结束时触发，参数为当前触摸位置
    public event Action<Vector3> OnDragEnd;
    
    // 长按事件：长按开始时触发
    public event Action OnLongPressStart;
    // 长按事件：长按结束时触发
    public event Action OnLongPressEnd;

    private bool isDragging = false;
    private Vector3 dragStartPos;
    private const float dragThreshold = 0.2f;
    
    private bool isLongPress = false;
    private float touchStartTime;
    private const float longPressThreshold = 0.5f;

    private void Update()
    {
        if (Input.touchCount == 1)
        {
            Touch touch = Input.GetTouch(0);
            Vector3 touchPos = Camera.main.ScreenToWorldPoint(touch.position);

            HandleDrag(touch, touchPos);	// 拖拽检测函数
            HandleLongPress(touch);			// 长按检测函数
        }
    }
	// 与基本实现中Update函数的实现基本一致，重复代码省略
    private void HandleDrag(Touch touch, Vector3 touchPos)
    {
        // 原来的三个Debug.Log分别替换成
        // OnDragStart?.Invoke(touchPos);
        // OnDrag?.Invoke(touchPos);
        // OnDragEnd?.Invoke(touchPos);
    }
    // 与基本实现中Update函数的实现基本一致，重复代码省略
    private void HandleLongPress(Touch touch)
    {
        // 原来的两个Debug.Log分别替换成
        // OnLongPressStart?.Invoke();
        // OnLongPressEnd?.Invoke();
    }
}

使用

在需要检测事件的地方监听对应的事件即可：

using UnityEngine;

public class Example : MonoBehaviour
{
    private void Start()
    {
        // 获取 InputHandler 的单例实例
        InputHandler inputHandler = InputHandler.Inst;
        // 注册拖拽中事件
        inputHandler.OnDrag += OnDragHandler;
        // 注册长按开始事件
        inputHandler.OnLongPressStart += OnLongPressStartHandler;
    }

    private void OnDragHandler(Vector3 position)
    {
        Debug.Log("拖拽中，位置: " + position);
    }

    private void OnLongPressStartHandler()
    {
        Debug.Log("长按开始");
    }
}

通过这种方式，我们可以将输入检测逻辑与具体的业务逻辑分离，使代码更加清晰和易于维护。

优化方向

现有的事件系统虽然能够检测到触摸位置，但对于具体物体的点击监听并不直接。以拖拽为例，通过事件监听能知道“拖拽行为在哪开始了”，但更多时候是需要GameObject对“自己被拖拽了”这件事作出反应。

为了更精确地判断触摸是否落在某个物体上，可以引入射线检测（Raycast）功能。这样，开发者可以更灵活地实现诸如“点击某个物体触发事件”的功能，从而提升交互的精确性和用户体验。
