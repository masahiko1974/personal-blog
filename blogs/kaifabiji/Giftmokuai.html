自然资源 (Gift) 模块开发文档

自然资源模块负责实现游戏中的自然资源（如野生植物、矿物等）的生成、展示和收集功能。该模块采用MVC架构设计，确保资源能够随机生成、持久化存储并实现交互式收集。

1. 核心类设计

1.1 数据模型

GiftData：资源数据类

  • int ID：资源类型ID
  • int GOID：资源全局唯一标识符
  • int Durability：资源耐久度
  • Position Position：资源位置

2.2 数据层（Model）

GiftModel：管理资源数据、处理业务逻辑

  • 维护所有资源对象，处理资源的生成与收集逻辑

    • 容器：Dictionary<int, GiftData> _giftDic（存储所有资源的字典）

    • 创建资源：

      GiftData CreateGift(Position pos, int id)：根据指定的ID和位置创建资源。查找设定信息_infoContainer，创建资源，加入_giftDic，并发送占地事件。

      GiftData CreateGift(Position pos)：从允许生成资源的白名单_allowedList随机选择资源类型，并在指定位置生成资源。创建后将其加入_giftDic，并发送占地事件。

    • 收集资源：

      bool ReduceGift(int goid)：根据GOID定位资源，减少其耐久度，计算掉落物并触发生成掉落物事件。当耐久度归零时销毁资源，并从_giftDic中移除。

  • 维护可生成资源的白名单，并更新白名单。

    • 容器：List<int> _allowedList（存储允许生成的资源ID列表）

    • 白名单更新： void UpdateallowedList(int level)：清空现有的白名单，然后从设定信息_infoContainer中，选择符合当前等级要求的资源，加入白名单。

  • 支持存档的序列化与反序列化。

    • 反序列化构造函数： GiftModel(Dictionary<int, GiftData> _giftDic, List<int> _allowedList)：加载已有存档，设置IsFirstLoad为false，反序列化_giftDic和_allowedList，并加载资源设定信息_infoContainer。

    • 普通构造函数： GiftModel()：新建模型，设置IsFirstLoad为true，实例化_giftDic与_allowedList，加载资源设定信息_infoContainer，并调用白名单更新方法。

2.3 控制层（Presenter）

GiftPresenter：协调Model和View的交互

  • 默认资源生成：

    • void GenerateGift(int id)：根据指定ID随机生成资源的位置，并检查该位置是否合法。如果位置不合法，则重新生成；若位置合法，则通过Model创建资源并交给View展示。

  • 事件监听：

    • 资源收集事件MsgDef.COLLECT_GIFT：触发资源收集逻辑，调用Model处理资源状态后，决定是否销毁资源，并由View更新显示。

    • 升级事件MsgDef.GATE_UPDATE：在玩家升级时调用Model的Update_allowedList方法，更新可生成资源的白名单。

  • 协程处理：

  • 随机生成资源：IEnumerator NaturalSow()：随机生成资源位置，并检查该位置是否适合放置资源。若位置不合法则短时间后重试；若合法，则通过Model创建资源并交给View展示。等待一段时间后继续生成资源。

2.4 视图层（View）

GiftView：负责资源的可视化展示

  • 维护场景中所有资源视图对象，并处理资源的创建与销毁逻辑
    • 容器：Dictionary<int, Gift> __giftDic（存储所有资源视图对象）
    • 展示资源：void ShowGift(GiftData giftData)：根据资源数据GiftData读取设定信息_infoContainer，异步加载资源，并计算其在场景中的位置。根据ID设置资源的精灵，并将其加入到_giftDic。
    • 销毁资源：void DestroyGift(int goid)：根据GOID定位资源视图对象，交给资源管理器ABResMgr销毁，并从_giftDic中移除。

2.5 视图模型

Gift：玩家交互入口，处理点击收集、显示和更新。

  • 采集资源void OnTap()

    在实现ITappableMono接口的基础上实现检测到点击后发送MsgDef.COLLECT_GIFT事件

  • 设置精灵图void SetSprite(int giftID) 根据资源ID加载对应的精灵图

4. 优化方向

  1. 优化资源生成算法：当前的生成逻辑每次生成三个资源，可以改为每隔一定时间生成一个资源，这样更符合自然生成的规律。
  2. 增加生成条件限制：可以根据环境条件（如气候、季节等）限制某些资源的生成，增强游戏的真实感和策略性。
  3. 简化白名单序列化：白名单中的资源不需要进行序列化存储，可以通过实时更新来减少存储负担。
